# OM Automate current feature inventory

**Audit date:** 2026-07-18
**Baseline:** `om-automate/main` at `9844a2f9a1996b8c8135a9e7bbde6a72f41df5ed`
**Scope:** User-visible and administrator-visible behaviour discovered in the UI, routers, services, persistence models, agent tools and tests.

## Status legend

- **Implemented** — a concrete UI/API/service path exists and representative automated tests cover it. Live third-party use still requires valid configuration.
- **Partial** — meaningful functionality exists, but an important part of the named product capability is absent or split across incompatible paths.
- **Broken** — a confirmed contradiction or missing link prevents the intended end-to-end behaviour.
- **Degraded** — usable, but a confirmed reliability, safety, fallback or consistency defect materially weakens it.
- **Unverified** — implementation exists, but this audit did not verify the real browser/platform/provider side effect.
- **Mock-only** — only a mock/demo path exists. No discovered user-facing route was classified this way; test mocks generally exercise real production code.

Paths and line numbers are evidence anchors, not claims that every branch in a large file was exercised. Tests listed are representative rather than exhaustive. “None” in the Agent tool column means the GUI/API feature is not currently exposed as a dedicated tool.

## Inventory conclusions

The current codebase is feature-rich and contains real implementations rather than a mock shell. The most important status distinctions are:

- **Implemented foundations:** authentication, users and 2FA; central chat; sessions/history; documents; notes; local/CalDAV calendar; IMAP/SMTP email; contacts; search/research; model endpoints; memory; skills; MCP; gallery; provider/device-flow adapters; API tokens/webhooks.
- **Partial product domains:** general agent creation, task/project management, meeting management, Google Calendar as a native provider, durable notifications, complete backup/restore, unified usage/audit and the target central OM assistant.
- **Confirmed broken promises:** generic action approval and incognito non-persistence.
- **Degraded safety/reliability:** agent tool execution, Stop/cancellation, process-local detached runs, scheduler resumability, tool-registry consistency and timeout enforcement.
- **Still requiring real environment verification:** third-party OAuth/provider calls, large model download/serve, image providers, vault, signed-PDF workflows, mobile devices and the complete one-click installation path.

Future feature work must update this matrix when a UI, route, service, store, tool, provider, test or status changes.
