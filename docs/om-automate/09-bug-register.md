# Bug and Risk Register

## Method

This register is based on code tracing, static searches, focused tests, a native startup, and an authenticated browser smoke test at upstream commit `9844a2f9a1996b8c8135a9e7bbde6a72f41df5ed`.

SAFE-002 checkpoint-B and the execution-helper remediation entries were reconciled against the current working tree. The remediation's focused/related gate is **275 passed**. The current restricted full suite reached **4,600 passed, 3 skipped, 20 failed, 8 warnings in 133.07 seconds**; all 20 failures are sandbox-denied loopback TCP, Unix-socket, or DNS cases and no remediation/registry/policy assertion failed. A socket-enabled rerun could not start because escalation hit the account usage limit until **2026-07-25**, so the current tree does not have a passing full-suite/startup/browser release result. Checkpoint A's older socket-enabled 4,538-pass result applies only to its prior code.

suite reached **4,950 passed, 20 environment-blocked socket/DNS failures, 3
skipped and 10 warnings**; all 65 tests in the affected files passed with local
socket access. Registry/authorization, exact approval, cancellation,
verification, sandbox, prompt-boundary, incognito and reasoning controls are

external evidence rather than inferred success.

Personal PrivateOS Phase 4 was reconciled on 2026-08-21. The expanded domain
gate passed **165 tests**; the restricted full suite reached **4,960 passes**
with the same 20 environment-blocked socket/DNS cases, and all 65 affected-file
tests passed with local access. Knowledge source deletion invalidates
derivatives, durable memory rejects incognito content, meeting claims retain
source spans, and routine definitions survive service restart. Optional

The initial broad scan found approximately 256 `TODO`, 2 `FIXME`, 5 `HACK`, 14 `XXX`, 16 `NotImplemented`, 54 `temporary`, 25 `deprecated`, 1,747 `except Exception`, 100 `console.log`, 474 `localhost`, and 2,084 `Odysseus` matches outside the new audit documents and virtual environment. These counts include legitimate documentation/tests and are triage inputs, not automatically bugs.

Severity definitions:

- **Critical** — credible secret compromise, privilege takeover, irreversible action, or silent data loss.
- **High** — broken safety boundary, major correctness/reliability failure, or release blocker.
- **Medium** — material degradation or maintainability risk with a bounded workaround.
- **Low** — polish, portability, or documentation defect with limited immediate impact.

## Positive controls to retain

- Authentication is enabled by default; localhost auth bypass is disabled.
- Non-administrators are blocked from coarse high-risk capabilities.
- File confinement already uses realpath checks and includes useful symlink protections, although its allowed roots are too broad.
- External content is explicitly marked untrusted in prompt assembly.
- Recursive settings redaction, CSP/security headers, encrypted/masked Google values, bcrypt API-token hashing, outbound-webhook SSRF/DNS pinning/HMAC, and loopback-only Compose binds are valuable foundations.
- Provider fallback avoids switching after visible response content has begun, preventing mixed-provider answers.
- Repetition breaking and detached SSE replay provide useful resilience primitives, but need durable state and cancellation integration.

## Release gate

No issue rated Critical or High may remain unresolved for the production-quality local release. A status may move to `Resolved` only when the focused regression, related suite, full blocking suite, startup, and applicable manual browser/provider verification all pass and the fix is linked to an ADR or implementation record.
